## A. What to run on your own machine (in this order)

Assumes WSL2 (Ubuntu) or Linux/macOS (native Windows is not supported; dropped 28 Nov).

A stage that is merely slow is normal, a stage with 0% CPU is a real hang: tell me). Both must print `0 failures` and no `WARNING: ThreadSanitizer`. TSan does not exist for macOS ARM with Apple clang the same way; on the Mac just run `run_tests.sh`.
3. **Record the platform.** `python3 tools/inspect_platform.py --name <short-id>` (e.g. `ryzen-wsl2`) -> commit `results/platform_<short-id>.json`. Do this on EVERY machine, including the Mac and any native-Windows run.
4. **Freeze the real graph (ONE person, ONCE).**
   First `python tools/check_osm_access.py` (shows which OSM hosts you can reach). Then `pip install osmnx networkx` and `python tools/export_graph.py --out data/snapshot_hcmc` (bounding box via Overpass; no Nominatim request). 26. **Why is the windowed optimistic list flat? + per-operation latency table (27 Nov, changes_39; ryzen-wsl2 only).** Extract the zip, `make`, then
   `python3 tools/opt_diag.py --platform ryzen-wsl2 --jemalloc /usr/lib/x86_64-linux-gnu/libjemalloc.so.2` (install it first with `sudo apt install libjemalloc2` if the file is missing; without `--jemalloc` the allocator test is skipped; add `--dry-run` to see the commands). It uses the scalar preset at 6 threads, pinned, 5 repetitions, and runs `win_coarse_ttas` (reference) and `win_opt_ttas` with and without jemalloc, plus add / pop_min latency for the plain and windowed lists at 1 and 6 threads. Expect about 10-20 minutes. Send `results/ryzen-wsl2/opt_diag/opt_diag_summary.md`. The two other machines do not need it: the latency table and the explanation are properties of the list implementations, so one machine is enough for the report (run it there too only if time allows).
   How to read it: `validate steps` much larger than `find steps` = the validation walk from the head dominates; high `retries / attempt` = optimistic walks are invalidated; `retire CAS fails` = contention on the retired-node stack; if the jemalloc rows move relative to the default rows the allocator is involved. The counters are off unless `--diag` is given (one relaxed atomic read per call).
